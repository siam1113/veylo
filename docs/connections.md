# Connections setup

The Connections tab supports 13 services: Google Calendar, Outlook Calendar, iCloud Calendar, ClickUp, Asana, Trello, Jira Cloud, Notion, Todoist, Microsoft To Do, Linear, GitHub Issues, and Slack. Connections read data on demand; Google Calendar and Outlook Calendar both create approved events and sync autonomously in the background. Previews disclose their limits and whether more items exist.

Every provider supports **more than one connected account** — connecting a second Google or Outlook account (or a second Notion workspace, Slack workspace, etc.) adds a new account rather than replacing the existing one. Reconnecting the *same* account (same email/workspace/site, as reported by the provider itself) updates that account's tokens in place instead of creating a duplicate. The Connections tab lists every connected account per provider, with its own Reconnect/Disconnect/Sync-now actions; the thoughts/time views show a small account badge next to the provider icon on any synced or pushed item so accounts of the same provider stay distinguishable. Each connected account can also be given a personal nickname and a single emoji icon (the pencil button next to its name in Connections) — purely cosmetic (`PATCH /integrations/:id`, stored in that row's `metadata`), never sent to the provider or touched by any sync/push logic.

Outlook previews the next 30 days in the default calendar. iCloud previews the next 30 days across up to five calendars, capped at 100 events. ClickUp, Asana, Trello, Linear, and GitHub show open assigned tasks/cards/issues. Todoist includes open tasks in shared projects; Microsoft To Do reads up to five lists. Work previews show up to 100 items. Slack previews the 50 most recent searchable messages sent by the connected user. Google Calendar previews the next 30 days from the primary calendar, titles included. **Keep as thought** explicitly saves the selected Slack message or Google Calendar event (as a meeting-kind thought) and its source link through ClearHead's existing durable local queue; it does not post to Slack or write to a calendar. Provider preview contents otherwise remain in memory rather than being imported into thoughts automatically.

Google Calendar requests `calendar.freebusy` (availability checks), `calendar.events.owned` (creating/updating only events ClearHead itself created), and `calendar.events.readonly` (reading upcoming event titles for the preview/Keep-as-thought flow above). Widening to `calendar.events.readonly` after it previously wasn't requested means existing connections must reconnect — their stored grant won't include it until the user goes through consent again. The same applies to Outlook's `Calendars.ReadWrite` scope (widened from the previous read-only `Calendars.ReadBasic`) and to Slack's optional `identity.basic`/`identity.email` user scope (used only to label a connected Slack account) — existing connections keep working but won't gain the new capability/label until reconnected.

### Autonomous calendar sync and pushing to a calendar

Both Google Calendar and Outlook Calendar run the same background pipeline: a worker tick fans out one sync job per connected calendar account (not per owner — each of a user's several Google/Outlook accounts syncs independently) roughly every hour (`CALENDAR_SYNC_INTERVAL_MS`, default `3600000`), pulling new/changed/cancelled events into ClearHead. Dedup is keyed by provider event id; a renamed thought's title is never silently overwritten by a stale provider-side title once ClearHead's copy has diverged from what the provider last reported. The Connections tab's "Sync all"/per-account refresh buttons, and the Time tab's refresh button, trigger an on-demand sync job for the relevant account(s) without waiting for the next scheduled tick.

**Add to Calendar** can push a single thought to more than one connected calendar at once — the confirmation modal lists every connected Google/Outlook account with a checkbox. Google retains its original idempotency trick (a deterministic, client-specified event id); Outlook has no equivalent (Microsoft Graph always assigns its own event id), so its push instead claims a row before calling Graph and sets an `IdempotencyKey` preference header to reduce (not eliminate) retry-duplication risk. A thought's first-ever push also becomes its "primary" calendar link (what every existing single-calendar UI binding shows); further pushes to additional calendars are tracked separately and don't disturb the primary link.

If Connect previously displayed a generic warning, check the API environment: missing provider credentials were producing HTTP 503, which the server intentionally masked as an internal error. The catalog now exposes only configuration readiness, the UI labels missing setup, and Connect returns an actionable 409 if called before configuration. Access-token-only connections (including ClickUp) are recognized without requiring a refresh token. OAuth returns to Connections and reports its result inline.

1. Apply migrations using `npm run db:migrate`; `0014_more_connection_providers.sql` and `0016_personal_and_team_connections.sql` extend the one-time OAuth state provider constraint. Render runs migrations before deployment.
2. Set `OAUTH_STATE_SECRET` (at least 32 random characters) and `TOKEN_ENCRYPTION_KEY` on the API. Keep existing values when upgrading; replacing the encryption key makes existing tokens unreadable. Never put secrets in `VITE_` variables.
3. Register each desired OAuth provider app. Set its `*_CLIENT_ID`, `*_CLIENT_SECRET`, and `*_REDIRECT_URI` on the API (see `.env.example` and `render.yaml`). The redirect must exactly match `https://YOUR_API/v1/integrations/PROVIDER/callback`, where PROVIDER is `google`, `outlook`, `clickup`, `asana`, `trello`, `jira`, `notion`, `todoist`, `microsoft_todo`, `linear`, `github`, or `slack`. Environment prefixes use the uppercase provider ID, including `MICROSOFT_TODO`. Asana requires HTTPS redirects, including local testing through a secure tunnel. iCloud does not use OAuth.
4. Set `WEB_ORIGIN` to the web app's origin and restart/redeploy the API. Reload Connections, choose Connect, and grant access in the provider's own consent screen.

Provider registration details:

- [Microsoft identity authorization](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow): register a confidential **Web** app, supporting organizational and personal Microsoft accounts if both are needed. Delegated scopes are `Calendars.ReadWrite offline_access`. Outlook uses Microsoft Graph `me/calendarView`/`me/calendarView/delta` for previews and background sync (UTC responses), and `me/events` to push approved time blocks. It does not request mail access. The connected account's email (`me.mail`/`me.userPrincipalName`) is read once at connect time purely to label the account for multi-account display — ClearHead never reads mail content.
- [ClickUp authentication](https://developer.clickup.com/docs/authentication): a workspace admin/owner creates the OAuth app. Users choose authorized workspaces. ClickUp currently issues a non-expiring access token without a refresh token; ClearHead only invokes read endpoints, although ClickUp does not offer granular read-only OAuth scopes.
- [Asana OAuth](https://developers.asana.com/docs/oauth): allow `tasks:read workspaces:read users:read`, register the HTTPS redirect, and ensure distribution permits the intended workspaces.
- [Trello confidential OAuth](https://developer.atlassian.com/cloud/trello/guides/rest-api/oauth-2-confidential-client-usage/): register a confidential OAuth 2.0 client with `read:member:trello read:board:trello read:card:trello offline_access`. Use the Trello client credentials, not the existing Jira client's credentials. PKCE is included.
- [Todoist API](https://developer.todoist.com/api/v1/): register an OAuth app with `data:read`. ClearHead uses the v1 tasks endpoint, including its cursor-based pagination indicator. Non-expiring access tokens are supported.
- [Microsoft To Do](https://learn.microsoft.com/en-us/graph/api/todotasklist-list-tasks?view=graph-rest-1.0): register a Microsoft confidential Web app with delegated `Tasks.Read offline_access`. It can share an app registration with Outlook if both exact callback URLs and permissions are registered; the two ClearHead connections store separate grants. Due dates are shown as calendar dates.
- [Linear OAuth](https://linear.app/developers/oauth-2-0-authentication): register a client with `read`, the exact callback, and PKCE. Store and rotate the refresh token. Queries read the signed-in user's assigned issues, excluding completed/canceled work.
- [GitHub App user authorization](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app): create a **GitHub App**, configure repository Issues as read-only (Metadata is implicit), register the callback and install the app on the intended repositories. Use the App's client ID and client secret, not its numeric App ID or private key. No broad OAuth `repo` scope is requested. Both expiring user tokens with refresh and non-expiring tokens are supported. [Assigned-issues responses](https://docs.github.com/en/rest/issues/issues#list-issues-assigned-to-the-authenticated-user) can include pull requests, which ClearHead excludes. Dates are milestone deadlines.
- [Slack OAuth](https://docs.slack.dev/authentication/installing-with-oauth/): add **User Token Scope** `search:read`, not a bot scope. Register the callback and permit installation for the desired workspace. ClearHead extracts `authed_user.access_token` and supports token rotation. The permission can search messages accessible to the user, but ClearHead's [search query](https://docs.slack.dev/reference/methods/search.messages/) is restricted to `from:me`. No bot, posting, or write scopes are requested. Workspace policy can require administrator approval.

### iCloud Calendar

Only `TOKEN_ENCRYPTION_KEY` is required on the API. In Connections, enter the Apple Account email and an [Apple app-specific password](https://support.apple.com/en-us/102654), which requires two-factor authentication. Never enter the main Apple Account password. The form clears the password after each attempt; credentials are verified through CalDAV before being encrypted in the database. They are not stored in browser persistence or returned through the catalog/status APIs.

ClearHead invokes only PROPFIND and REPORT. App-specific passwords themselves are not calendar read-only grants. Discovery and redirects are restricted to HTTPS `caldav.icloud.com` and Apple's numbered CalDAV hosts. XML entities/DTDs are rejected and responses are size-limited. The server requests [CalDAV recurrence expansion](https://datatracker.ietf.org/doc/html/rfc4791#section-9.6.5); unresolved recurrence or local time values produce an explanatory error rather than incorrect dates. Disconnect clears ClearHead's credential copy and reminds the user to revoke the app-specific password in Apple Account settings.

Tokens stay encrypted in the API database. Authorization states are owner-scoped, expire after ten minutes, and can be consumed once. Outlook, Asana, Trello, Microsoft To Do, Linear, and GitHub include PKCE. Expiring OAuth tokens are refreshed when needed. Disconnect immediately clears ClearHead's saved tokens; the UI also explains removal from the provider's connected-app settings. Deleting a ClearHead account reports the same remaining-grant guidance.
